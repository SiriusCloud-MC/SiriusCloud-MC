A Minecraft server cloud that tells you what it is doing.

Describe a group once. SiriusCloud keeps it true: it starts servers when players arrive, stops them when they leave, registers them with your proxy the moment they are ready, and hands over to another node if one dies.

Features

Everything a network needs, and nothing to wire together.

The cloud runs your servers. The network features run on the cloud, so they work on every server with nothing installed there.

Servers follow your players

Autoscaling on player load, rolling restarts that never drop capacity, template rollouts and scheduled restarts.

Clustering with failover

Run three nodes as one. If the leader dies, another takes over in seconds while every server keeps running.

A proxy that lists nothing

Velocity learns every server as it becomes ready. Modern forwarding is configured on both ends for you.

Social

Parties that follow their leader, friends with join notices, /msg across servers, /seen and /playtime.

Moderation

Timed bans checked at the proxy, mutes, kicks, staff chat, /find and /jump. Bans follow name changes.

Matchmaking

/play queues fill the fullest open server first, keep parties together and start a server when nothing has room.

Ranks everywhere

Cloud-wide permission groups with prefixes in chat, above heads and in a tab list sorted by rank. Or keep LuckPerms, synced without Redis.

Your data, kept

JSON files, MySQL, MariaDB, PostgreSQL or MongoDB. Player profiles, a shared key-value store, and backups of static servers.

Monitoring

TPS, MSPT and heap from every server, a Prometheus endpoint, and Discord alerts for crashes, lag and failed backups.

Updates itself

New releases are downloaded, checksum-verified and installed by a restart that keeps servers running. Your files are migrated, backed up first.

Consoles you can read

attach Lobby-1 hands the console to that server. A crash pushes its last lines to you unasked.

REST API & web panel

A token-protected HTTP API and a live panel, served by the node itself and bound to localhost until you widen it.

How it works

Three pieces, one API.

The node decides, wrappers do, and the same CloudDriver interface works from a module, a plugin or the node itself.

NodeOwns every group, port and scheduling decision, and the network's data. Has the console you type into.
WrapperOne per machine. Holds no policy of its own, so machine number two is just a second wrapper.
APIOne interface everywhere. The network features are modules built on nothing but that API.
Clustering

Lose a node, not your network.

Several nodes run as one. The leader runs the control plane, followers keep a live copy of its data, and when it goes away one of them takes over. Servers keep running throughout. Wrappers and plugins find the new leader by themselves.

  • No split brain. A leader that loses its majority stops before a replacement can exist.
  • Stale leaders are ignored. Every client remembers the newest term and refuses an older one.
  • Only up-to-date nodes lead, on a build at least as new as the data.
  • Clean hand-over: shutdown on the leader moves leadership in under a second.

A real failover, from the test log

Get started

No JSON to hand-edit.

Both halves ask what they need on first start, and suggest answers from your actual machine.

Build it

Needs a Java 25 JDK available to Gradle.

git clone https://github.com/SiriusCloud-MC/SiriusCloud-MC
cd SiriusCloud-MC && ./gradlew dist

Start the node

It asks for a name, a RAM budget and a port, and offers a Lobby and a proxy group. It prints a wrapper secret.

cd build/dist && ./start-node.sh

Start a wrapper

On each machine that runs servers. It asks for the node address, the secret, and which installed Java to use.

./start-wrapper.sh

Play

The Lobby is below its minimum, so it starts. Point players at the proxy port.

CloudDriver cloud = CloudDriver.instance();

// move anyone, wherever they are
cloud.players().connectToGroup(uuid, "BedWars");

// matchmaking stops sending players here
cloud.services().setState(ServiceProperties.STATE_INGAME);

// shared state with expiry, across every server
cloud.store().set("event:double-xp", "on", Duration.ofHours(2));

Honest status

Better you know now than after downloading.

This is early software that is honest about being early.

Tested end to end
  • Nodes, wrappers, dynamic and static servers
  • Velocity registration and modern forwarding
  • Attach console and crash reports
  • Cloud-wide player layer
  • REST API and panel
  • Cluster failover on one machine
Newer, less proven
  • Autoscaling and rollouts
  • Network features and ranks
  • Databases, backups, Docker
  • Clustering across real machines
  • Covered by unit tests; reports welcome
Known limits
  • Windows is written for but not yet run
  • Built-in ranks do not apply on Velocity
  • Fabric servers do not autoscale
  • Two-node clusters need a manual promote

A cloud you can read the source of.
